# Nested Classes

## Introduction

Java supports four types of nested classes — inner classes (non-static member classes), static nested classes, local classes, and anonymous classes. While "inner class" and "nested class" are often used interchangeably in casual conversation, they have distinct technical meanings in Java. A nested class is any class declared within another class, while an inner class specifically refers to a non-static nested class that holds an implicit reference to its enclosing instance. Understanding all four nested class types is essential for writing idiomatic Java code, implementing design patterns like Builder and Iterator, and avoiding common pitfalls such as memory leaks and unnecessary coupling. Each type has different scoping rules, access capabilities, and use cases.

- [ ] Choose the appropriate nested class type based on the use case

## Why This Concept Exists

### The Problem

In complex software systems, helper classes, data structures, and implementation details often need to be logically grouped with their parent class. However, creating separate top-level files for every helper class leads to namespace pollution and makes it harder to understand the relationships between classes. Additionally, some helper classes need access to private members of their parent class.

### The Solution

Nested classes allow you to declare classes inside other classes, keeping related code together. The four types provide different levels of coupling and access, from tightly coupled inner classes (with outer references) to completely independent static nested classes.

### Real-World Analogy

Think of a company hierarchy. A department (outer class) contains teams (inner classes). Some teams work exclusively within the department (non-static inner classes — they need department resources). Some teams are self-contained but still organized under the department (static nested classes — they have their own resources). Some teams are formed temporarily for specific projects (local classes). And some individuals are hired for one-off tasks (anonymous classes).

## Internal Working

### The Four Types at a Glance

| Type | Static? | Outer Reference | Scope | Typical Use |
|------|---------|-----------------|-------|-------------|
| Inner class (member) | No | Yes (implicit) | Class-level | Tightly coupled helpers |
| Static nested class | Yes | No | Class-level | Independent helpers |
| Local class | No | Yes (if in instance context) | Method-level | Method-specific implementations |
| Anonymous class | No | Yes (if in instance context) | Expression-level | One-off implementations |

### Compilation Output

For each nested class, the compiler generates a separate `.class` file named `OuterClass$NestedClass.class`. Anonymous classes get numeric suffixes: `OuterClass$1.class`, `OuterClass$2.class`, etc.

```
MyClass.class
MyClass$InnerClass.class
MyClass$StaticNested.class
MyClass$1LocalClass.class  (if multiple local classes exist)
MyClass$1.class            (first anonymous class)
MyClass$2.class            (second anonymous class)
```

### Access to Outer Members

Inner classes and local classes can access both static and instance members of the outer class. Static nested classes can only access static members of the outer class. All types can access public members. Private member access is facilitated through synthetic accessor methods generated by the compiler.

## Syntax

```java
class Outer {
    // Static nested class
    static class StaticNested {
        // Can access only static members of Outer
    }

    // Inner class (non-static member class)
    class Inner {
        // Can access all members of Outer (including private)
    }

    void method() {
        // Local class — visible only within this method
        class LocalClass {
            // Can access final/effectively final local variables
            // Can access outer instance members if called from instance context
        }

        // Anonymous class — creates an instance without a named class
        Runnable r = new Runnable() {
            @Override
            public void run() {
                // Implementation here
            }
        };
    }
}
```

## Easy Examples

### Example 1: All Four Nested Class Types

**Problem Statement**: Demonstrate the declaration and usage of all four nested class types in a single outer class.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

class Company {
    private String companyName = "TechCorp";

    static class Department {
        private String name;

        Department(String name) {
            this.name = name;
        }

        void display() {
            // Cannot access companyName here (static context)
            System.out.println("Department: " + name);
        }
    }

    class Employee {
        private String name;

        Employee(String name) {
            this.name = name;
        }

        void display() {
            // Can access companyName (has outer reference)
            System.out.println(name + " works at " + companyName);
        }
    }

    void createProjectTeam() {
        class ProjectMember {
            private String role;

            ProjectMember(String role) {
                this.role = role;
            }

            void display() {
                // Can access companyName and method local variables
                System.out.println(role + " at " + companyName);
            }
        }

        ProjectMember lead = new ProjectMember("Project Lead");
        lead.display();
    }
}

public class NestedTypesDemo {
    public static void main(String[] args) {
        // Static nested class
        Company.Department dept = new Company.Department("Engineering");
        dept.display();

        // Inner class
        Company company = new Company();
        Company.Employee emp = company.new Employee("Alice");
        emp.display();

        // Local class (created inside method)
        company.createProjectTeam();

        // Anonymous class
        Runnable task = new Runnable() {
            @Override
            public void run() {
                System.out.println("Anonymous class task running");
            }
        };
        task.run();
    }
}
```

**Expected Output**:
```
Department: Engineering
Alice works at TechCorp
Project Lead at TechCorp
Anonymous class task running
```

**Best Practices**:
- Use static nested classes when you don't need access to outer instance members
- Use inner classes for helpers that are logically part of the outer class
- Prefer local classes or anonymous classes for method-scoped implementations

### Example 2: Local Class for Custom Comparator

**Problem Statement**: Use a local class inside a method to create a custom `Comparator` for sorting.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

import java.util.Arrays;
import java.util.Comparator;
import java.util.List;

class StudentSorter {
    static void sortByLastName(List<String> students) {
        class LastNameComparator implements Comparator<String> {
            @Override
            public int compare(String s1, String s2) {
                String last1 = s1.substring(s1.lastIndexOf(' ') + 1);
                String last2 = s2.substring(s2.lastIndexOf(' ') + 1);
                return last1.compareTo(last2);
            }
        }

        students.sort(new LastNameComparator());
    }

    public static void main(String[] args) {
        List<String> students = Arrays.asList(
                "Alice Johnson", "Bob Smith", "Charlie Brown", "Diana Prince"
        );

        System.out.println("Before: " + students);
        sortByLastName(students);
        System.out.println("After:  " + students);
    }
}
```

**Expected Output**:
```
Before: [Alice Johnson, Bob Smith, Charlie Brown, Diana Prince]
After:  [Charlie Brown, Alice Johnson, Diana Prince, Bob Smith]
```

**Best Practices**:
- Use local classes when the implementation is only needed within a single method
- Local classes can access final or effectively final local variables
- Consider lambda expressions as a more concise alternative for single-method interfaces

### Example 3: Static Nested Class for Builder Pattern

**Problem Statement**: Implement a `NetworkConfig` class with a static nested `Builder` class.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

class NetworkConfig {
    private final String host;
    private final int port;
    private final boolean useSsl;
    private final int timeoutMs;

    private NetworkConfig(Builder builder) {
        this.host = builder.host;
        this.port = builder.port;
        this.useSsl = builder.useSsl;
        this.timeoutMs = builder.timeoutMs;
    }

    static class Builder {
        private String host = "localhost";
        private int port = 8080;
        private boolean useSsl = false;
        private int timeoutMs = 30000;

        Builder host(String host) { this.host = host; return this; }
        Builder port(int port) { this.port = port; return this; }
        Builder useSsl(boolean useSsl) { this.useSsl = useSsl; return this; }
        Builder timeoutMs(int timeoutMs) { this.timeoutMs = timeoutMs; return this; }

        NetworkConfig build() {
            if (host == null || host.isEmpty()) throw new IllegalArgumentException("Host required");
            if (port <= 0 || port > 65535) throw new IllegalArgumentException("Invalid port");
            return new NetworkConfig(this);
        }
    }

    @Override
    public String toString() {
        return String.format("NetworkConfig{host='%s', port=%d, ssl=%b, timeout=%dms}",
                host, port, useSsl, timeoutMs);
    }

    public static void main(String[] args) {
        NetworkConfig config = new NetworkConfig.Builder()
                .host("api.example.com")
                .port(443)
                .useSsl(true)
                .timeoutMs(5000)
                .build();

        System.out.println(config);
    }
}
```

**Expected Output**:
```
NetworkConfig{host='api.example.com', port=443, ssl=true, timeout=5000ms}
```

**Best Practices**:
- Use static nested classes for Builders — they don't need the outer instance
- Make the outer class constructor private to force use of the Builder
- Validate in the Builder's `build()` method, not in the constructor

## Medium Examples

### Example 1: Map.Entry — JDK's Use of Static Nested Classes

**Problem Statement**: Demonstrate how `Map.Entry` works as a static nested interface and how to use it effectively.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

import java.util.HashMap;
import java.util.Map;

class InventorySystem {
    private Map<String, Integer> stock = new HashMap<>();

    void addItem(String item, int quantity) {
        stock.put(item, quantity);
    }

    void printInventory() {
        for (Map.Entry<String, Integer> entry : stock.entrySet()) {
            System.out.printf("  %-20s : %d units%n", entry.getKey(), entry.getValue());
        }
    }

    String findLowStockItem() {
        Map.Entry<String, Integer> lowest = null;
        for (Map.Entry<String, Integer> entry : stock.entrySet()) {
            if (lowest == null || entry.getValue() < lowest.getValue()) {
                lowest = entry;
            }
        }
        return lowest != null ? lowest.getKey() : null;
    }

    public static void main(String[] args) {
        InventorySystem inventory = new InventorySystem();
        inventory.addItem("Laptops", 50);
        inventory.addItem("Keyboards", 200);
        inventory.addItem("Mice", 15);
        inventory.addItem("Monitors", 35);

        System.out.println("Inventory:");
        inventory.printInventory();
        System.out.println("Low stock: " + inventory.findLowStockItem());
    }
}
```

**Expected Output**:
```
Inventory:
  Laptops              : 50 units
  Keyboards            : 200 units
  Mice                 : 15 units
  Monitors             : 35 units
Low stock: Mice
```

**Code Walkthrough**: `Map.Entry<K,V>` is a static nested interface within `Map`. It represents a key-value pair. By making it static nested (not inner), `Entry` instances can exist independently of any `Map` instance, which is essential for entries that outlive their parent map.

### Example 2: Local Class for File Processing

**Problem Statement**: Implement a file processor that uses a local class to parse different file formats within the same method.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

import java.util.Arrays;
import java.util.List;

class LogProcessor {
    static void processLogs(List<String> logs) {
        class LogEntry {
            private String timestamp;
            private String level;
            private String message;

            LogEntry(String raw) {
                String[] parts = raw.split("\\|", 3);
                timestamp = parts.length > 0 ? parts[0].trim() : "UNKNOWN";
                level = parts.length > 1 ? parts[1].trim() : "INFO";
                message = parts.length > 2 ? parts[2].trim() : "";
            }

            boolean isError() {
                return level.equals("ERROR") || level.equals("FATAL");
            }

            @Override
            public String toString() {
                return String.format("[%s] %s: %s", timestamp, level, message);
            }
        }

        int errorCount = 0;
        for (String raw : logs) {
            LogEntry entry = new LogEntry(raw);
            System.out.println(entry);
            if (entry.isError()) errorCount++;
        }
        System.out.println("Total errors: " + errorCount);
    }

    public static void main(String[] args) {
        List<String> logs = Arrays.asList(
                "2024-01-15 10:30:00|INFO|Application started",
                "2024-01-15 10:30:05|WARN|Disk usage above 80%",
                "2024-01-15 10:30:10|ERROR|Connection timeout to database",
                "2024-01-15 10:30:15|INFO|Retrying connection"
        );

        processLogs(logs);
    }
}
```

**Expected Output**:
```
[2024-01-15 10:30:00] INFO: Application started
[2024-01-15 10:30:05] WARN: Disk usage above 80%
[2024-01-15 10:30:10] ERROR: Connection timeout to database
[2024-01-15 10:30:15] INFO: Retrying connection
Total errors: 1
```

**Code Walkthrough**: The `LogEntry` local class is defined inside `processLogs` and is only visible within that method. It encapsulates the parsing logic for a single log format. If other methods need similar parsing, extract it to a static nested class or top-level class.

**Alternative Solution**: You could use an anonymous class or a lambda with a `Function<String, LogEntry>` but the local class provides the best readability for multi-line implementations.

### Example 3: Anonymous Class for Event Listener Registration

**Problem Statement**: Build a GUI-like event system using anonymous inner classes to register multiple listeners with different behaviors.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

import java.util.ArrayList;
import java.util.List;

interface MouseAction {
    void onMouseEvent(int x, int y);
}

class MouseEventSystem {
    private List<MouseAction> listeners = new ArrayList<>();

    void addListener(MouseAction listener) {
        listeners.add(listener);
    }

    void triggerEvent(int x, int y) {
        for (MouseAction listener : listeners) {
            listener.onMouseEvent(x, y);
        }
    }
}

public class EventListenerDemo {
    public static void main(String[] args) {
        MouseEventSystem system = new MouseEventSystem();

        // Anonymous class 1: Logger
        system.addListener(new MouseAction() {
            @Override
            public void onMouseEvent(int x, int y) {
                System.out.println("LOG: Mouse event at (" + x + ", " + y + ")");
            }
        });

        // Anonymous class 2: Boundary checker
        system.addListener(new MouseAction() {
            @Override
            public void onMouseEvent(int x, int y) {
                if (x < 0 || y < 0 || x > 800 || y > 600) {
                    System.out.println("WARNING: Event outside bounds!");
                }
            }
        });

        // Anonymous class 3: Counter
        system.addListener(new MouseAction() {
            private int count = 0;

            @Override
            public void onMouseEvent(int x, int y) {
                count++;
                System.out.println("Total events: " + count);
            }
        });

        system.triggerEvent(100, 200);
        System.out.println("---");
        system.triggerEvent(-10, 50);
    }
}
```

**Expected Output**:
```
LOG: Mouse event at (100, 200)
Total events: 1
---
LOG: Mouse event at (-10, 50)
WARNING: Event outside bounds!
Total events: 2
```

**Code Walkthrough**: Three anonymous classes implement the `MouseAction` interface. Each has different behavior but the same interface. The third anonymous class maintains state (`count`), which is unique to each instance — a subtle but important point.

## Hard Examples

### Example 1: Deeply Nested Classes for AST (Abstract Syntax Tree)

**Problem Statement**: Implement a simple expression evaluator using deeply nested classes to represent an abstract syntax tree.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

abstract class Expression {
    abstract double evaluate();

    static class Number extends Expression {
        private double value;

        Number(double value) {
            this.value = value;
        }

        @Override
        double evaluate() { return value; }

        @Override
        public String toString() { return String.valueOf(value); }
    }

    static class BinaryOperation extends Expression {
        enum Operator { ADD, SUBTRACT, MULTIPLY, DIVIDE }

        private final Operator op;
        private final Expression left;
        private final Expression right;

        BinaryOperation(Operator op, Expression left, Expression right) {
            this.op = op;
            this.left = left;
            this.right = right;
        }

        @Override
        double evaluate() {
            return switch (op) {
                case ADD -> left.evaluate() + right.evaluate();
                case SUBTRACT -> left.evaluate() - right.evaluate();
                case MULTIPLY -> left.evaluate() * right.evaluate();
                case DIVIDE -> {
                    double r = right.evaluate();
                    if (r == 0) throw new ArithmeticException("Division by zero");
                    yield left.evaluate() / r;
                }
            };
        }

        @Override
        public String toString() {
            return "(" + left + " " + op + " " + right + ")";
        }
    }

    static class UnaryOperation extends Expression {
        enum Operator { NEGATE, ABS }

        private final Operator op;
        private final Expression operand;

        UnaryOperation(Operator op, Expression operand) {
            this.op = op;
            this.operand = operand;
        }

        @Override
        double evaluate() {
            return switch (op) {
                case NEGATE -> -operand.evaluate();
                case ABS -> Math.abs(operand.evaluate());
            };
        }

        @Override
        public String toString() {
            return switch (op) {
                case NEGATE -> "(-" + operand + ")";
                case ABS -> "|" + operand + "|";
            };
        }
    }
}

public class ExpressionEvaluatorDemo {
    public static void main(String[] args) {
        // Build: (3 + 4) * (2 - 1)
        Expression expr = new Expression.BinaryOperation(
                Expression.BinaryOperation.Operator.MULTIPLY,
                new Expression.BinaryOperation(
                        Expression.BinaryOperation.Operator.ADD,
                        new Expression.Number(3),
                        new Expression.Number(4)
                ),
                new Expression.BinaryOperation(
                        Expression.BinaryOperation.Operator.SUBTRACT,
                        new Expression.Number(2),
                        new Expression.Number(1)
                )
        );

        System.out.println("Expression: " + expr);
        System.out.println("Result: " + expr.evaluate());

        // Build: -(5 + 3)
        Expression unary = new Expression.UnaryOperation(
                Expression.UnaryOperation.Operator.NEGATE,
                new Expression.BinaryOperation(
                        Expression.BinaryOperation.Operator.ADD,
                        new Expression.Number(5),
                        new Expression.Number(3)
                )
        );

        System.out.println("Expression: " + unary);
        System.out.println("Result: " + unary.evaluate());
    }
}
```

**Unit Tests**:

```java
package academy.javaengineering.oop.nestedclasses;

import static org.junit.jupiter.api.Assertions.*;
import org.junit.jupiter.api.Test;

class ExpressionTest {
    @Test
    void testAddition() {
        Expression expr = new Expression.BinaryOperation(
                Expression.BinaryOperation.Operator.ADD,
                new Expression.Number(2),
                new Expression.Number(3)
        );
        assertEquals(5.0, expr.evaluate(), 0.001);
    }

    @Test
    void testDivisionByZero() {
        Expression expr = new Expression.BinaryOperation(
                Expression.BinaryOperation.Operator.DIVIDE,
                new Expression.Number(10),
                new Expression.Number(0)
        );
        assertThrows(ArithmeticException.class, expr::evaluate);
    }

    @Test
    void testNestedExpression() {
        // (1 + 2) * 3 = 9
        Expression expr = new Expression.BinaryOperation(
                Expression.BinaryOperation.Operator.MULTIPLY,
                new Expression.BinaryOperation(
                        Expression.BinaryOperation.Operator.ADD,
                        new Expression.Number(1),

```

**Execution Flow**: Each node in the AST evaluates its children recursively. `Number` nodes return their value. `BinaryOperation` evaluates both sides and applies the operator. `UnaryOperation` evaluates its operand and applies the transformation.

**Complexity**: O(n) where n is the number of nodes in the expression tree.

**Best Practices**:
- Use static nested classes for AST nodes — they don't need outer references
- Implement `toString()` for debugging
- Use enums for operators to leverage type safety and switch expressions

### Example 2: Nested Class Chain for Configuration Hierarchy

**Problem Statement**: Build a hierarchical configuration system using nested classes that support defaults, overrides, and environment-specific settings.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

import java.util.HashMap;
import java.util.Map;

class AppConfig {
    private final DatabaseConfig database;
    private final ServerConfig server;
    private final Map<String, String> overrides;

    private AppConfig(Builder builder) {
        this.database = builder.databaseBuilder.build();
        this.server = builder.serverBuilder.build();
        this.overrides = builder.overrides;
    }

    static class Builder {
        final DatabaseConfig.Builder databaseBuilder = new DatabaseConfig.Builder();
        final ServerConfig.Builder serverBuilder = new ServerConfig.Builder();
        final Map<String, String> overrides = new HashMap<>();

        DatabaseConfig.Builder database() { return databaseBuilder; }
        ServerConfig.Builder server() { return serverBuilder; }
        Builder override(String key, String value) { overrides.put(key, value); return this; }

        AppConfig build() {
            return new AppConfig(this);
        }
    }

    static class DatabaseConfig {
        final String url;
        final int poolSize;
        final boolean sslEnabled;

        private DatabaseConfig(Builder builder) {
            this.url = builder.url;
            this.poolSize = builder.poolSize;
            this.sslEnabled = builder.sslEnabled;
        }

        static class Builder {
            private String url = "jdbc:mysql://localhost:3306/mydb";
            private int poolSize = 10;
            private boolean sslEnabled = false;

            Builder url(String url) { this.url = url; return this; }
            Builder poolSize(int poolSize) { this.poolSize = poolSize; return this; }
            Builder sslEnabled(boolean sslEnabled) { this.sslEnabled = sslEnabled; return this; }

            DatabaseConfig build() { return new DatabaseConfig(this); }
        }

        @Override
        public String toString() {
            return String.format("DB{url='%s', pool=%d, ssl=%b}", url, poolSize, sslEnabled);
        }
    }

    static class ServerConfig {
        final String host;
        final int port;
        final int threadCount;

        private ServerConfig(Builder builder) {
            this.host = builder.host;
            this.port = builder.port;
            this.threadCount = builder.threadCount;
        }

        static class Builder {
            private String host = "0.0.0.0";
            private int port = 8080;
            private int threadCount = Runtime.getRuntime().availableProcessors();

            Builder host(String host) { this.host = host; return this; }
            Builder port(int port) { this.port = port; return this; }
            Builder threadCount(int count) { this.threadCount = count; return this; }

            ServerConfig build() { return new ServerConfig(this); }
        }

        @Override
        public String toString() {
            return String.format("Server{host='%s', port=%d, threads=%d}", host, port, threadCount);
        }
    }

    @Override
    public String toString() {
        return String.format("AppConfig{%n  %s%n  %s%n  overrides=%s%n}",
                database, server, overrides);
    }

    public static void main(String[] args) {
        AppConfig config = new AppConfig.Builder()
                .database()
                    .url("jdbc:mysql://prod-db:3306/app")
                    .poolSize(20)
                    .sslEnabled(true)
                .server()
                    .host("api.production.com")
                    .port(443)
                    .threadCount(16)
                .override("cache.ttl", "300")
                .override("feature.darkMode", "true")
                .build();

        System.out.println(config);
    }
}
```

**Execution Flow**: The builder pattern with nested classes creates a type-safe, hierarchical configuration. Each nested `Builder` can only configure its own section. The root `AppConfig.Builder` orchestrates the build process.

**Complexity**: O(1) for building — all operations are simple field assignments.

**Best Practices**:
- Use nested builders for hierarchical configurations
- Set sensible defaults in each builder
- Validate in `build()` methods
- Keep builders static to avoid unnecessary outer references

## Interview Questions

### Easy

1. **What are the four types of nested classes in Java?**
   Inner classes (non-static member classes), static nested classes, local classes, and anonymous classes. Inner classes have implicit outer references. Static nested classes don't. Local classes are defined inside methods. Anonymous classes are unnamed classes defined in a single expression.

2. **Why would you use a static nested class over an inner class?**
   Static nested classes don't hold a reference to the outer instance, making them more memory-efficient. Use them when the nested class doesn't need access to instance members of the outer class.

3. **Can a local class access non-final local variables of its enclosing method?**
   No. Since Java 8, local classes can access effectively final variables (variables assigned once), but they cannot modify them. This is because the local class captures a copy of the variable, not a reference.

### Intermediate

4. **How does the compiler handle private member access from inner classes?**
   The compiler generates synthetic accessor methods (package-private) in the outer class that provide get/set access to private fields. The inner class calls these methods instead of accessing private fields directly. This can be observed using `javap -p`.

5. **What is the scoping difference between local and anonymous classes?**
   Local classes are named and can be referenced multiple times within their enclosing method. Anonymous classes are unnamed and are always instantiated in a single expression. Local classes can extend a class or implement an interface. Anonymous classes can only extend one class or implement one interface.

6. **How do anonymous classes interact with local variables?**
   Anonymous classes can only access local variables that are final or effectively final (assigned exactly once). The variable's value is captured at the time the anonymous class is created, not when the method executes.

### Hard

7. **Explain the memory model implications of nested classes in concurrent code.**
   Inner classes holding references to outer instances can prevent garbage collection in concurrent contexts. The implicit outer reference is not volatile or synchronized, so modifications to outer fields by the inner class may not be visible to other threads. Use synchronization or volatile fields when inner classes share mutable state across threads.

8. **How do generic nested classes differ from non-generic ones? Can an inner class have its own type parameters?**
   Yes, nested classes can have their own type parameters independent of the outer class. `Outer<T>.Inner<U>` means the inner class has its own generic type. Static nested classes like `Map.Entry<K,V>` demonstrate this — `Entry` has its own type parameters independent of `Map`.

## Common Pitfalls

### 1. Memory Leak from Long-Lived Inner Class References

**Wrong**:
```java
class Service {
    private int state = 0;

    void registerCallback() {
        CallbackManager.register(new Callback() {
            @Override
            public void onEvent() {
                state++; // Anonymous class holds reference to Service
            }
        });
        // Service cannot be garbage collected while Callback exists
    }
}
```

**Right**:
```java
class Service {
    private int state = 0;

    void registerCallback() {
        final int[] stateHolder = {state}; // Effectively final local
        CallbackManager.register(new Callback() {
            @Override
            public void onEvent() {
                stateHolder[0]++; // Only captures local variable
            }
        });
    }
}
```

Or better: use a weak reference or lambda that doesn't capture the outer instance.

### 2. Using Inner Class When Static Nested Suffices

**Wrong**:
```java
class HashMap<K, V> {
    class Node<K, V> {  // Unnecessary outer reference for every entry
        K key;
        V value;
        Node<K, V> next;
    }
}
```

**Right**:
```java
class HashMap<K, V> {
    static class Node<K, V> {  // No outer reference — more efficient
        K key;
        V value;
        Node<K, V> next;
    }
}
```

If the nested class doesn't use outer instance members, make it static.

### 3. Confusing Local Class Scope

**Wrong**:
```java
class Outer {
    void method() {
        class Local { void foo() {} }
    }

    void otherMethod() {
        Local l = new Local(); // COMPILE ERROR — Local is not visible here
        l.foo();
    }
}
```

**Right**:
```java
class Outer {
    void method() {
        class Local { void foo() {} }
        Local l = new Local(); // OK — same method scope
        l.foo();
    }
}
```

Local classes are only visible within the method in which they are declared.

## Best Practices

1. **Prefer static nested classes over inner classes** — Avoid the unnecessary outer reference when it's not needed.
2. **Keep nested classes private or package-private** — They are implementation details, not public API.
3. **Use anonymous classes sparingly** — Prefer lambda expressions for functional interfaces and named classes for complex logic.
4. **Avoid local classes in long methods** — If a method needs a helper class, consider extracting it to a static nested class.
5. **Be aware of compilation artifacts** — Each nested class generates a separate `.class` file, which can increase JAR size and class loading overhead.

## Real World Usage

### How JDK Uses This

`HashMap.Node` is a static nested class. `Map.Entry` is a static nested interface. `AbstractList.ListItr` is a private inner class used for iteration. `Thread.State` and `Thread.UncaughtExceptionHandler` are nested types. `Collections.UnmodifiableList` wraps the original list using a static nested class.

### How Spring Uses This

Spring's `BeanDefinitionBuilder` uses static nested classes for different bean scopes. `@Configuration` classes use inner `@Bean` methods. `TestPropertySource` and `ActiveProfiles` are nested annotations. `Mockito.mock()` returns anonymous class implementations of the mocked interface.

### Enterprise Usage

Enterprise applications use nested classes for configuration builders, event handlers, data transfer objects, strategy implementations, and factory methods. The Builder pattern with static nested classes is standard for immutable configuration objects. Local classes are used in stream processing and data transformation pipelines.

## Summary

- Java supports four nested class types: inner, static nested, local, and anonymous
- Inner classes hold implicit references to outer instances — watch for memory leaks
- Static nested classes are more memory-efficient and preferred when outer access isn't needed
- Local classes are method-scoped and can access effectively final local variables
- Anonymous classes provide one-off implementations but prefer lambdas for functional interfaces
- Each nested class generates a separate `.class` file — this affects packaging and class loading
