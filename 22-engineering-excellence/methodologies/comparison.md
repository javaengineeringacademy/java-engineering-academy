# Methodology Comparison Matrix

A comprehensive comparison of software development methodologies to help teams choose the right approach.

## Quick Comparison

| Methodology | Approach | Roles | Cadence | Best For |
|------------|----------|-------|---------|----------|
| Waterfall | Sequential | PM, Dev, QA | Phases | Fixed requirements |
| V-Model | Sequential + Testing | PM, Dev, QA, Tester | Phases | Safety-critical |
| Spiral | Risk-driven Iterative | PM, Dev, Risk Analyst | Cycles | Large risky projects |
| Iterative | Repeated cycles | PM, Dev Team | Iterations | Evolving requirements |
| Incremental | Piece by piece | PM, Dev Teams | Increments | Phased delivery |
| RAD | Time-boxed | PM, Dev, User | Time-boxed | Fast prototypes |
| RUP | Structured Iterative | PM, Dev, Architect | Phases | Enterprise projects |
| Agile | Adaptive | Self-organizing | Time-boxed | Changing requirements |
| Scrum | Sprint-based | PO, SM, Team | Sprints | Product development |
| Kanban | Flow-based | Team members | Continuous | Operations, maintenance |
| XP | Engineering-focused | Pair developers | Iterations | High-quality code |
| SAFe | Scaled Agile | PO, SM, RTE, Teams | PIs | Enterprise programs |
| LeSS | Scaled Scrum | PO, Teams | Sprints | Multi-team products |
| DevOps | Culture + Practices | Dev + Ops teams | Continuous | Fast delivery |
| Lean | Value-focused | Self-organizing | Continuous | Efficiency |

## Detailed Comparison

### Waterfall vs Agile

| Aspect | Waterfall | Agile |
|--------|-----------|-------|
| Requirements | Fixed upfront | Evolving |
| Delivery | End of project | Frequent |
| Testing | After development | Continuous |
| Customer involvement | Beginning and end | Throughout |
| Documentation | Comprehensive | Just enough |
| Risk management | Late discovery | Early and continuous |
| Change | Resisted | Welcomed |

### Scrum vs Kanban

| Aspect | Scrum | Kanban |
|--------|-------|--------|
| Cadence | Fixed sprints | Continuous flow |
| Roles | PO, SM, Team | No prescribed roles |
| WIP Limits | Sprint backlog | Explicit WIP limits |
| Planning | Sprint planning | Just-in-time |
| Metrics | Velocity | Cycle time |
| Best for | Product development | Operations/maintenance |

### SAFe vs LeSS

| Aspect | SAFe | LeSS |
|--------|------|------|
| Complexity | High | Low |
| Prescriptiveness | High | Low |
| Roles | Many defined roles | Minimal roles |
| Scaling | Multiple levels | Simple scaling |
| Training | Extensive | Minimal |
| Best for | Large enterprises | Mature Scrum teams |

## Decision Matrix

| Scenario | Recommended | Alternative |
|----------|-------------|-------------|
| Fixed budget, fixed scope | Waterfall | RUP |
| Safety-critical, regulated | V-Model | Waterfall |
| Large risky project | Spiral | Iterative |
| Startup, unclear requirements | Scrum | Kanban |
| High code quality needed | XP | Scrum |
| Operations team | Kanban | Lean |
| 50+ person program | SAFe | LeSS |
| Need both dev + ops | DevOps | Lean |
| Efficiency focus | Lean | Kanban |
| Fast prototypes | RAD | Agile |

## Maturity Considerations

| Team Maturity | Recommendation |
|---------------|----------------|
| New to agile | Start with Scrum |
| Experienced Scrum | Add XP practices |
| Multiple teams | Consider LeSS or SAFe |
| Operations focus | Adopt Kanban |
| Need structure | RUP or SAFe |
| Want simplicity | LeSS or Scrum |

## Industry Recommendations

| Industry | Primary | Why |
|----------|---------|-----|
| Healthcare | V-Model, Waterfall | Regulatory compliance |
| Finance | Waterfall, SAFe | Audit requirements |
| Aerospace | V-Model, Spiral | Safety-critical |
| Startups | Scrum, Kanban | Speed and flexibility |
| Enterprise | SAFe, RUP | Scale and governance |
| Gaming | Scrum, Kanban | Rapid iteration |
| E-commerce | Scrum, DevOps | Fast delivery |
