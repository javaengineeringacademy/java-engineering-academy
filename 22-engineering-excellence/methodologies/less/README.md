# Large-Scale Scrum (LeSS)

## Overview

Large-Scale Scrum is a lightweight framework for scaling Scrum to multiple teams working on one product. Created by **Craig Larman** and **Bas Vodde**, LeSS emphasizes simplicity and minimal additional structure.

## LeSS Frameworks

- **LeSS** - 2-8 teams, one Product Backlog
- **LeSS Huge** - 10+ teams, multiple Product Owners

## Key Principles

1. **Empirical Process Control** - Transparency, inspection, adaptation
2. **Whole Product Focus** - Teams deliver end-to-end value
3. **Continuous Improvement** - Regular retrospectives at all levels
4. **Customer-Centric** - Direct feedback from users
5. **Lean Thinking** - Eliminate waste, optimize flow

## When to Use

- Multiple Scrum teams working on one product
- Want to minimize additional process overhead
- Teams can handle increased responsibility
- Organizations value simplicity over structure
- Products with clear, shared backlog

## Pros

- Minimal additional process
- Preserves Scrum's simplicity
- Encourages technical excellence
- Strong focus on whole-product value
- Transparent cross-team coordination

## Cons

- Requires mature Scrum teams
- Can be challenging without strong technical practices
- Less guidance than SAFe
- May require significant organizational change
- Not suitable for all team structures

## Real-World Example

**Nokia Networks** - Nokia Networks used LeSS to scale Scrum across multiple teams working on telecommunications infrastructure, maintaining agility while coordinating complex development.
