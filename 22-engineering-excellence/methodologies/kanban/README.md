# Kanban Method

## Overview

Kanban is a flow-based methodology that visualizes work, limits work in progress (WIP), and optimizes flow. Created by **David Anderson** for software development, Kanban focuses on continuous delivery and process improvement.

## Core Practices

1. **Visualize the Workflow** - Use a Kanban board to show work states
2. **Limit Work in Progress (WIP)** - Set limits on concurrent tasks
3. **Manage Flow** - Monitor and optimize throughput
4. **Make Process Policies Explicit** - Define rules clearly
5. **Implement Feedback Loops** - Regular review and adjustment
6. **Improve Collaboratively** - Evolve through experimentation

## When to Use

- Teams with variable work arrival rates
- Operations and maintenance work
- When continuous delivery is needed
- Teams wanting to improve flow
- Organizations not ready for Scrum

## Pros

- Visualizes work and bottlenecks
- Flexible and easy to implement
- No prescribed roles or ceremonies
- Focuses on flow efficiency
- Reduces multitasking and context switching

## Cons

- No time-boxed iterations
- May lack structure for some teams
- Requires discipline to maintain WIP limits
- Less emphasis on planning
- Can be challenging without clear definition of done

## Real-World Example

**Zara** - Zara's supply chain uses Kanban principles to manage fast fashion production, with visual signals triggering new production based on actual demand.
