# Engineering Playbooks

## Overview

This module provides practical engineering playbooks covering two major areas: company case studies from leading technology organizations and modernization strategies for legacy system transformation. These playbooks serve as reference guides for architects, engineers, and technical leads navigating complex engineering challenges.

## Company Playbooks

Company playbooks document how leading technology companies solve engineering problems at scale. Each playbook examines the technology stack, architecture decisions, operational practices, and hard-won lessons from real-world production systems.

### Key Companies Covered

- **Netflix** - Chaos engineering, microservices, Zuul, Eureka
- **Uber** - Domain-oriented microservices, Kafka, event-driven architecture
- **Stripe** - Payment processing, idempotency, distributed systems
- **Google** - Borg, Spanner, SRE practices, global-scale infrastructure
- **WhatsApp** - Erlang/Elixir, messaging at billions of scale
- **Amazon** - Two-pizza teams, API-first, order processing
- **Booking.com** - Experimentation platforms, A/B testing at scale
- **LinkedIn** - Espresso, Kafka origins, Voldemort storage
- **Airbnb** - Service mesh, SOA migration, frontend architecture

## Modernization Playbooks

Modernization playbooks provide step-by-step strategies for transforming legacy systems. Each playbook covers migration patterns, tooling, risk mitigation, and measurable outcomes from real migration projects.

### Key Migrations Covered

- **Monolith to Microservices** - Strangler fig pattern, decomposition strategies
- **Framework Migrations** - Struts to Spring Boot, EJB to Spring, JSP to React
- **Database Migrations** - Oracle to PostgreSQL, schema evolution
- **Infrastructure Migrations** - VM to containers, WebSphere to Kubernetes
- **Platform Migrations** - On-premises to AWS, Kafka to Redpanda
- **Language Upgrades** - Java 8 to Java 21, Log4j migration
- **Toolchain Modernization** - SVN to Git, Jenkins to GitHub Actions

## Using These Playbooks

Each playbook follows a consistent structure:

1. **Context** - Why the change was needed
2. **Strategy** - The approach taken
3. **Implementation** - How it was executed
4. **Results** - Measurable outcomes
5. **Lessons Learned** - What worked and what did not

## When to Apply

Use company playbooks when you need inspiration for solving similar architectural challenges. Use modernization playbooks when planning or executing a transformation initiative. Cross-reference both when making technology decisions that affect multiple layers of the stack.
