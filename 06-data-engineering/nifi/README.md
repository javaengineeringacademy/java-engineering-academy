## Flow Files

Flow files are the core data abstraction in NiFi:

### Flow File Structure

```
┌─────────────────────────────────────────────┐
│                Flow File                    │
│  ┌─────────────────────────────────────────┐│
│  │  Content (payload)                      ││
│  │  - The actual data being processed      ││
│  │  - Stored in content repository         ││
│  └─────────────────────────────────────────┘│
│  ┌─────────────────────────────────────────┐│
│  │  Attributes (metadata)                  ││
│  │  - Key-value pairs                      ││
│  │  - Used for routing and decisions       ││
│  │  - Example: filename, date, status      ││
│  └─────────────────────────────────────────┘│
└─────────────────────────────────────────────┘
```

### Flow File Lifecycle

1. **Created**: Generated by source processors
2. **Modified**: Transformed by processors
3. **Routed**: Directed to appropriate paths
4. **Terminated**: Output or removed

### Flow File Attributes

```java
// Common attributes
flowFile.getAttribute("filename")      // Original filename
flowFile.getAttribute("path")          // Directory path
flowFile.getAttribute("mime.type")     // Content type
flowFile.getAttribute("uuid")          // Unique identifier
flowFile.getAttribute("date")          // Creation date

// Custom attributes
flowFile.putAttribute("custom.key", "custom.value");
```

### Content vs Metadata

- **Content**: Actual data (stored separately)
- **Attributes**: Metadata about the data
- **Relationship**: Attributes describe content

**Routing Processors**

### Processor Configuration

```
┌─────────────────────────────────────────────┐
│  Processor: GetFile                        │
├─────────────────────────────────────────────┤
│  Scheduling                                │
│  ┌─────────────────────────────────────────┐│
│  │  Run Duration: 1 sec                   ││
│  │  Concurrent Tasks: 1                   ││
│  │  Scheduling Strategy: Timer            ││
│  └─────────────────────────────────────────┘│
│                                            │
│  Properties                                │
│  ┌─────────────────────────────────────────┐│
│  │  Directory: /data/incoming              ││
│  │  Filename Pattern: *.csv                ││
│  │  Batch Size: 10                        ││
│  └─────────────────────────────────────────┘│
│                                            │
│  Relationships                             │
│  ┌─────────────────────────────────────────┐│
│  │  success → [next processor]            ││
│  │  failure → [error handler]             ││
│  └─────────────────────────────────────────┘│
└─────────────────────────────────────────────┘
```

### Custom Processors

```java
@Tags({"custom", "example"})
@CapabilityDescription("Example custom processor")
public class MyProcessor extends AbstractProcessor {
    
    @Property(
        value = "my.property",
        description = "Custom property"
    )
    private PropertyDescriptor myProperty;
    
    @Relationship("success")
    private Relationship success;
    
    @Override
    protected void init(final ProcessorContext context) {
        super.init(context);
        this.myProperty = getPropertyDescriptor();
    }
    
    @Override
    public void onTrigger(final ProcessContext context, 
                          final ProcessSession session) throws ProcessException {
        FlowFile flowFile = session.get();
        if (flowFile == null) {
            return;
        }
        
        try {
            // Process the flow file
            session.putAttribute(flowFile, "processed", "true");
            session.transfer(flowFile, success);
        } catch (Exception e) {
            session.transfer(flowFile, failure);
        }
    }
}
```

### Processor Lifecycle

1. **onScheduled**: Processor is about to start
2. **onTrigger**: Main processing logic
3. **onUnscheduled**: Processor is stopping
4. **onStopped**: Processor has stopped

Connections link processors together:

### Connection Configuration

```
┌─────────────────────────────────────────────┐
│  Connection: Processor A → Processor B     │
├─────────────────────────────────────────────┤
│  Name: Data Flow Connection                │
│  Comments: Main data path                  │
│                                            │
│  Queue Configuration                       │
│  ┌─────────────────────────────────────────┐│
│  │  Back Pressure:                         ││
│  │    Object Threshold: 10,000            ││
│  │    Size Threshold: 1 GB                ││
│  │                                        ││
│  │  Flowfile Expiration: 10 minutes       ││
│  │  Load Balance Strategy: Round Robin    ││
│  └─────────────────────────────────────────┘│
│                                            │
│  Prioritization                            │
│  ┌─────────────────────────────────────────┐│
│  │  Priority: FIFO                        ││
│  │  (Or Priority Attribute, etc.)         ││
│  └─────────────────────────────────────────┘│
└─────────────────────────────────────────────┘
```

### Load Balancing Strategies

- **Round Robin**: Distribute equally across targets
- **Single Connection**: Send all to one target
- **Event-Driven**: Send based on events

### Connection Priorities

- **FIFO**: First In, First Out
- **LIFO**: Last In, First Out
- **Priority Attribute**: Use flowfile attribute
- **Penalty Time**: Older flowfiles first

## Back Pressure

Back pressure prevents system overload:

### Configuration

```
┌─────────────────────────────────────────────┐
│  Back Pressure Settings                     │
├─────────────────────────────────────────────┤
│                                            │
│  Object Threshold                          │
│  ┌─────────────────────────────────────────┐│
│  │  Default: 10,000 flowfiles             ││
│  │  Max: Unlimited                        ││
│  │  Recommended: Based on processing rate ││
│  └─────────────────────────────────────────┘│
│                                            │
│  Size Threshold                            │
│  ┌─────────────────────────────────────────┐│
│  │  Default: 1 GB                         ││
│  │  Max: Unlimited                        ││
│  │  Recommended: Based on memory          ││
│  └─────────────────────────────────────────┘│
│                                            │
│  Expiration                                │
│  ┌─────────────────────────────────────────┐│
│  │  Default: 10 minutes                   ││
│  │  Purpose: Remove stale flowfiles       ││
│  │  Action: Route to expired relationship ││
│  └─────────────────────────────────────────┘│
└─────────────────────────────────────────────┘
```

### How Back Pressure Works

```
┌────────────┐      ┌─────────────────────────────┐
│ Processor  │ ──── │ Connection Queue            │
│   A        │      │ Object: 8,500 / 10,000     │
└────────────┘      │ Size: 750 MB / 1 GB        │
                    │ Status: OK (not full)       │
                    └─────────────────────────────┘
                               │
                               ▼
                    ┌─────────────────────────────┐
                    │ Connection Queue            │
                    │ Object: 9,800 / 10,000     │
                    │ Size: 950 MB / 1 GB        │
                    │ Status: WARNING (almost full)│
                    └─────────────────────────────┘
                               │
                               ▼
                    ┌─────────────────────────────┐
                    │ Connection Queue            │
                    │ Object: 10,000 / 10,000    │
                    │ Size: 1 GB / 1 GB          │
                    │ Status: FULL (back pressure)│
                    └─────────────────────────────┘
                               │
                               ▼
                    ┌─────────────────────────────┐
                    │ Upstream Processor Paused   │
                    └─────────────────────────────┘
```

### Best Practices

1. **Monitor Queue Depth**: Watch for back pressure
2. **Adjust Thresholds**: Based on processing capacity
3. **Set Expiration**: Prevent stale data accumulation
4. **Use Alerts**: Notify when back pressure occurs
5. **Scale Processing**: Add more concurrent tasks

## Provenance

Provenance tracks data lineage:

### Provenance Events

**Content Modified**
- Data transformation occurred
- File was processed
- Record was updated

**Content Claimed**
- Data was claimed by processor
- Processing started

**Fork**
- Flow file split into multiple
- Parent-child relationship

**Merge**
- Multiple flow files combined
- History preserved

**Route**
- Flow file routed to relationship
- Routing decision recorded

### Provenance Repository

```
┌─────────────────────────────────────────────┐
│  Provenance Repository                     │
├─────────────────────────────────────────────┤
│  Storage: Disk-based                       │
│  Retention: 24 hours (configurable)        │
│  Compression: Enabled                      │
│  Indexing: Enabled for search              │
│                                            │
│  Query Capabilities                        │
│  ┌─────────────────────────────────────────┐│
│  │  - Search by flowfile UUID             ││
│  │  - Search by time range                ││
│  │  - Search by processor                 ││
│  │  - Search by event type                ││
│  │  - Search by attributes                ││
│  └─────────────────────────────────────────┘│
│                                            │
│  Storage Optimization                      │
```

## Data Provenance

NiFi tracks complete data lineage:

### Provenance Queries

```java
// Search by flowfile UUID
ProvenanceSearchEvent event = new ProvenanceSearchEvent();
event.setFlowFileUuid("uuid-123");

// Search by time range
event.setStartDate(startTime);
event.setEndDate(endTime);

// Search by processor
event.setProcessorId("processor-123");

// Search by event type
event.setEventType(ProvenanceEventType.CREATE);
```

### Provenance Events

```java
public class MyProvenanceEvent {
    public void trackCreation(FlowFile flowFile) {
        ProvenanceEventRecord event = ProvenanceEventRecord.create(
            ProvenanceEventType.CREATE,
            "MyProcessor",
            flowFile,
            "Created new flowfile"
        );
        context.provenanceReporter().reportEvent(event);
    }
    
    public void trackModification(FlowFile flowFile) {
        ProvenanceEventRecord event = ProvenanceEventRecord.create(
            ProvenanceEventType.MODIFY,
            "MyProcessor",
            flowFile,
            "Modified content"
        );
        context.provenanceReporter().reportEvent(event);
    }
}
```

### Provenance Benefits

1. **Lineage**: Track data origin
2. **Debugging**: Trace issues
3. **Compliance**: Meet regulatory requirements
4. **Security**: Audit data access
5. **Impact Analysis**: Understand dependencies
