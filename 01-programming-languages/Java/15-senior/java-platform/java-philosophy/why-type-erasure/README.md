# Why Type Erasure?

## Backward Compatibility with Java 1.4

### The Problem

Java 5 (2004) introduced generics, but the JVM already existed with millions of lines of bytecode. All existing libraries, frameworks, and applications were compiled to Java 1.4 bytecode.

### The Solution: Type Erasure

```java
// Java 5+ source code
List<String> list = new ArrayList<String>();
list.add("Hello");
String s = list.get(0);

// What the JVM sees (after compilation)
List list = new ArrayList();
list.add("Hello");
String s = (String) list.get(0); // Cast inserted
```

Type erasure means **generic type information is removed at compile time**. The JVM never sees `List<String>` - only `List`.

### Why This Was Chosen

1. **Backward compatibility**: Existing bytecode runs unchanged
2. **Performance**: No runtime overhead for type parameters
3. **Simplicity**: No JVM changes required
4. **Interoperability**: Generic and non-generic code can mix

## How Generics Are Implemented

### Compile-Time Transformation

```java
// Source code
public class Box<T> {
    private T value;
    
    public void set(T value) {
        this.value = value;
    }
    
    public T get() {
        return value;
    }
}

// After compilation (erased)
public class Box {
    private Object value;
    
    public void set(Object value) {
        this.value = value;
    }
    
    public Object get() {
        return value;
    }
}
```

### Bridge Methods

```java
// When overriding generic methods
public class StringBox extends Box<String> {
    @Override
    public void set(String value) {
        super.set(value);
    }
    
    @Override
    public String get() {
        return (String) super.get();
    }
}

// After compilation, bridge method added
public class StringBox extends Box {
    // Bridge method (generated by compiler)
    public void set(Object value) {
        set((String) value); // Calls the String version
    }
    
    public void set(String value) {
        super.set(value);
    }
    
    public String get() {
        return (String) super.get();
    }
}
```

### Bounds Checking

```java
// Source code
public <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}

// After erasure (with bounds)
public Comparable max(Comparable a, Comparable b) {
    return a.compareTo(b) >= 0 ? a : b;
}
```

## Consequences of Type Erasure

### Cannot Use instanceof with Generics

```java
// This doesn't work
List<String> list = new ArrayList<>();
if (list instanceof List<String>) {} // Compile error

// Why? The generic type is erased at runtime
// At runtime, it's just a List
if (list instanceof List) {} // This works
```

### Cannot Create Generic Arrays

```java
// This doesn't work
T[] array = new T[10]; // Compile error

// Why? Arrays know their component type at runtime
// But generic type is erased
String[] strings = new String[10]; // This works
```

### Cannot Create Generic Type Instances

```java
// This doesn't work
public <T> T createInstance() {
    return new T(); // Compile error
}

// Why? The constructor doesn't exist after erasure
// At runtime, we don't know what T is
```

### Cannot Use Generic Types in Static Context

```java
// This doesn't work
public class Box<T> {
    private static T value; // Compile error
}

// Why? Static members belong to class, not instance
// Generic type is per-instance
```

### Cannot Catch Generic Exceptions

```java
// This doesn't work
try {
    riskyOperation();
} catch (T e) {} // Compile error

// Why? Exception type is erased
// At runtime, we don't know what T is
```

## Workarounds

### TypeToken Pattern (Guava)

```java
// Capture generic type at runtime
TypeToken<List<String>> type = new TypeToken<List<String>>() {};
Type listType = type.getType(); // ParameterizedType

// Use with Gson
Gson gson = new Gson();
List<String> list = gson.fromJson(json, type.getType());
```

### Class Literal

```java
// Pass class literal for simple cases
public <T> T createInstance(Class<T> clazz) {
    return clazz.getDeclaredConstructor().newInstance();
}

// Usage
User user = createInstance(User.class);
```

### Generic Type Inference

```java
// Java 8+: Type inference
List<String> list = new ArrayList<>(); // Diamond operator
Map<String, List<Integer>> map = new HashMap<>(); // Inferred

// Method type inference
List<String> list = Arrays.asList("a", "b", "c");
```

### Reflection for Runtime Type Information

```java
// Store type information manually
public class TypedContainer<T> {
    private final Class<T> type;
    private T value;
    
    public TypedContainer(Class<T> type) {
        this.type = type;
    }
    
    public T getValue() {
        return value;
    }
    
    public void setValue(T value) {
        this.value = value;
    }
    
    public Class<T> getType() {
        return type;
    }
}

// Usage
TypedContainer<String> container = new TypedContainer<>(String.class);
```

### Annotation-Based Type Information

```java
// Use annotations to store generic type
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface GenericType {
    Class<?>[] value();
}

@GenericType(String.class)
public class MyList<T> {}

// At runtime, read annotation to get type
```

## Valhalla Project (Value Types May Change This)

### Project Goals

Project Valhalla aims to introduce **value types** to Java. This could potentially change how generics work.

### Potential Changes

```java
// Future: Reified generics
List<int> list = new ArrayList<int>(); // No boxing
if (list instanceof List<int>) {} // Might work
int[] array = new int[10]; // Already works
```

### What This Means

1. **Primitive generics**: `List<int>` instead of `List<Integer>`
2. **Reified types**: Generic type information preserved at runtime
3. **Performance**: Eliminate boxing overhead
4. **Backward compatibility**: Existing code must still work

### Timeline

- **Phase 1**: Value types (Java 21+)
- **Phase 2**: Primitive generics (future)
- **Phase 3**: Reified generics (distant future)

## Comparison with Other Languages

### C# (Reified Generics)

```csharp
// C# preserves generic type at runtime
List<string> list = new List<string>();
if (list is List<string>) {} // Works
typeof(List<string>) // Returns List<string>
```

**Pros**: No erasure, more powerful
**Cons**: Boxing for value types, more complex JVM

### Kotlin (Type Projections)

```kotlin
// Kotlin adds reified type parameters for inline functions
inline fun <reified T> isType(value: Any): Boolean {
    return value is T
}
```

**Pros**: Some reification in inline functions
**Cons**: Still erased for regular functions

### Scala (Manifests)

```scala
// Scala uses manifests for runtime type information
def create[T](implicit manifest: Manifest[T]): T = {
    manifest.runtimeClass.newInstance()
}
```

**Pros**: Explicit type information
**Cons**: Boilerplate, not true reification

## Best Practices

### 1. Use Type Tokens for Generic Type Information

```java
public abstract class TypeToken<T> {
    private final Type type;
    
    protected TypeToken() {
        Type superclass = getClass().getGenericSuperclass();
        ParameterizedType pt = (ParameterizedType) superclass;
        type = pt.getActualTypeArguments()[0];
    }
    
    public Type getType() { return type; }
}

// Usage
TypeToken<List<String>> token = new TypeToken<List<String>>() {};
```

### 2. Use Class Literals When Possible

```java
// Simpler than TypeToken for single type parameters
public <T> List<T> createList(Class<T> clazz) {
    return new ArrayList<>();
}

List<String> list = createList(String.class);
```

### 3. Avoid Unchecked Casts

```java
// Bad
List<String> list = (List<String>) rawList;

// Better
List<String> list = new ArrayList<>();
for (Object obj : rawList) {
    list.add((String) obj);
}
```

### 4. Document Generic Types

```java
/**
 * Process items of type T.
 * 
 * @param <T> the type of items to process
 * @param items the items to process
 */
public <T> void process(List<T> items) {
    // Implementation
}
```
