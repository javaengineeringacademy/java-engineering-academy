# Decision: BDD Testing

## When to Use BDD

**Use BDD when:**
- Requirements need to be clear to all stakeholders
- Acceptance criteria must be documented
- Cross-team collaboration is needed
- Living documentation is valuable

**Skip BDD when:**
- Simple unit tests are sufficient
- No business stakeholder involvement
- Rapid prototyping phase

## Gherkin Best Practices

1. Write scenarios from user perspective
2. Use Background for common setup
3. Use Scenario Outline for data-driven tests
4. Keep steps simple and reusable
5. Avoid technical details in scenarios

## BDD vs TDD

| Aspect | BDD | TDD |
|--------|-----|-----|
| Focus | Behavior | Implementation |
| Language | Natural language | Code |
| Audience | All stakeholders | Developers |
| Documentation | Living docs | Code comments |
