# 03 - Internals: Type Erasure Implementation

## Scope

This topic covers the internal implementation of type erasure in the Java compiler, including how generic types are transformed, bridge methods are generated, and runtime type information is preserved.

## Why It Exists

Understanding type erasure internals is critical for:

- Debugging ClassCastException that occur due to misunderstood erasure
- Understanding why certain generic patterns don't work
- Building frameworks that leverage reflection to access generic types
- Optimizing code that uses generics heavily

## How Type Erasure Works

Type erasure is a compile-time process that:

1. **Replaces type parameters** with their bounds (or `Object` if unbounded)
2. **Inserts casts** where the compiler needs to ensure type safety
3. **Generates bridge methods** to preserve polymorphism
4. **Preserves generic signatures** in class file metadata for reflection

## Compiler Transformation Steps

### Step 1: Type Parameter Replacement

```java
// Original
public class Box<T> {
    private T value;
    public T get() { return value; }
    public void set(T value) { this.value = value; }
}

// After erasure
public class Box {
    private Object value;
    public Object get() { return value; }
    public void set(Object value) { this.value = value; }
}
```

### Step 2: Cast Insertion

```java
// Original
Box<String> box = new Box<>();
String s = box.get();

// After erasure (simplified)
Box box = new Box();
String s = (String) box.get();  // Cast inserted
```

### Step 3: Bridge Method Generation

When a subclass overrides a generic method with a more specific return type, the compiler generates a bridge method:

```java
// Original
public class StringBox extends Box<String> {
    @Override
    public String get() { return "hello"; }
}

// After erasure
public class StringBox extends Box {
    @Override
    public String get() { return "hello"; }
    
    // Bridge method (generated by compiler)
    public Object get() { return this.get(); }
}
```

The bridge method ensures that the overridden method is properly dispatched at runtime.

## Bounded Type Erasure

When a type parameter has a bound, the bound is used instead of `Object`:

```java
// Original
public <T extends Number> double sum(List<T> list) {
    return list.stream()
        .mapToDouble(Number::doubleValue)
        .sum();
}

// After erasure
public double sum(List list) {
    return list.stream()
        .mapToDouble(((Number) element).doubleValue())
        .sum();
}
```

The type parameter `T extends Number` is replaced with `Number`, and casts to `Number` are inserted.

## Multiple Bounds Erasure

When a type parameter has multiple bounds, the first bound is used:

```java
// Original
public <T extends Comparable<T> & Serializable> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}

// After erasure
public Comparable max(Comparable a, Comparable b) {
    return a.compareTo(b) >= 0 ? a : b;
}
```

The type parameter `T extends Comparable<T> & Serializable` is replaced with `Comparable` (the first bound).

## Wildcard Erasure

Wildcards are erased differently:

```java
// Original
public void printList(List<?> list) { ... }
public void addNumber(List<? super Integer> list) { ... }

// After erasure
public void printList(List list) { ... }
public void addNumber(List list) { ... }
```

Wildcards are erased to their bounds (or `Object` for unbounded wildcards).

## Bridge Methods in Detail

Bridge methods are generated in several scenarios:

### Scenario 1: Covariant Return Types

```java
public class StringBox extends Box<String> {
    @Override
    public String get() { return "hello"; }
}
```

The compiler generates:

```java
public class StringBox extends Box {
    public String get() { return "hello"; }
    
    // Bridge method
    public Object get() { return this.get(); }
}
```

### Scenario 2: Type Parameter Erasure in Subclasses

```java
public class Wrapper<T> {
    private T value;
    public T getValue() { return value; }
}

public class StringWrapper extends Wrapper<String> {
    private String name;
    
    @Override
    public String getValue() { return name; }
}
```

The compiler generates:

```java
public class StringWrapper extends Wrapper {
    private String name;
    
    public String getValue() { return name; }
    
    // Bridge method
    public Object getValue() { return this.getValue(); }
}
```

## Runtime Type Information

Although type erasure removes generic type information at runtime, the Java reflection API can access generic signatures stored in the class file:

```java
// Get the generic superclass
Type genericSuperclass = StringBox.class.getGenericSuperclass();
ParameterizedType pt = (ParameterizedType) genericSuperclass;
Type[] typeArguments = pt.getActualTypeArguments();
System.out.println(typeArguments[0]); // class java.lang.String
```

This works because the generic signature is stored in the class file's `Signature` attribute, not in the bytecode instructions.

## Common Pitfalls

### 1. `instanceof` with Generic Types

```java
// COMPILE ERROR: Cannot use instanceof with generic types
if (obj instanceof List<String>) { }  // Error

// WORKAROUND: Use raw type or wildcard
if (obj instanceof List<?>) { }  // OK
```

### 2. Generic Array Creation

```java
// COMPILE ERROR: Cannot create generic arrays
T[] array = new T[10];  // Error

// WORKAROUND: Use Array.newInstance() or Object[]
Object[] array = new Object[10];  // OK
```

### 3. Static Members

```java
public class Box<T> {
    // COMPILE ERROR: Cannot have static members with type parameters
    private static T value;  // Error
    
    // OK: Static members without type parameters
    private static int count;  // OK
}
```

## Summary

| Concept | Key Takeaway |
|---------|--------------|
| Type erasure | Compile-time process, removes generic type parameters |
| Erasure rules | `T` → `Object`, `T extends X` → `X` |
| Bridge methods | Generated for polymorphism with covariant returns |
| Cast insertion | Compiler adds casts after generic method calls |
| Reflection | Generic signatures preserved in class file metadata |
| Pitfalls | No `instanceof`, no generic arrays, no static type params |
