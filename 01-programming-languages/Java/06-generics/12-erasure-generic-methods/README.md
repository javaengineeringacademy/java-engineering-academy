# 12 - Erasure of Generic Methods

> **Reading:** 45 min | **Practice:** 45 min

## Overview

Type erasure also applies to generic methods. The compiler removes type parameters from methods, inserts casts, and generates bridge methods to preserve polymorphism.

## Why It Exists

Generic method erasure exists because:
- Methods need the same compile-time type safety as classes
- The JVM executes raw bytecode, not generic bytecode
- Bridge methods ensure polymorphism works correctly with erasure

## How Generic Methods Are Erased

### Original Method

```java
public <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}
```

### After Erasure

```java
public Comparable max(Comparable a, Comparable b) {
    return a.compareTo(b) >= 0 ? a : b;
}
```

The type parameter `T extends Comparable<T>` is replaced with `Comparable` (the first bound).

## Bridge Methods for Generic Methods

When a subclass overrides a generic method, the compiler generates bridge methods:

### Original Code

```java
public class StringComparator implements Comparator<String> {
    @Override
    public int compare(String a, String b) {
        return a.compareTo(b);
    }
}
```

### After Erasure

```java
public class StringComparator implements Comparator {
    @Override
    public int compare(String a, String b) {
        return a.compareTo(b);
    }
    
    // Bridge method (generated by compiler)
    public int compare(Object a, Object b) {
        return this.compare((String) a, (String) b);
    }
}
```

## Varargs Heap Pollution

Generic methods with varargs can cause heap pollution:

```java
// WARNING: Possible heap pollution from parameterized varargs type
@SafeVarargs
public static <T> List<T> asList(T... elements) {
    return Arrays.asList(elements);
}
```

The `@SafeVarargs` annotation suppresses the warning when you're sure the method doesn't cause heap pollution.

## Common Pitfalls

### 1. Type Erasure in Overloading

```java
// COMPILE ERROR: These methods have the same erasure
public void method(List<String> list) { }
public void method(List<Integer> list) { }
// Both erase to: void method(List list)
```

### 2. Bridge Method Conflicts

```java
// COMPILE ERROR: Bridge method conflicts
public class Foo<T> implements Comparable<T> {
    public int compareTo(T other) { return 0; }
}

public class Bar extends Foo<String> {
    public int compareTo(String other) { return 0; }
    // Compiler generates: int compareTo(Object other) { return this.compareTo((String) other); }
    // But Foo already has: int compareTo(Object other) { return this.compareTo((String) other); }
}
```

## Performance Considerations

Generic method erasure happens at compile time, so there is no runtime performance cost. The JIT compiler can optimize away the casts in many cases.

## Summary

| Concept | Key Takeaway |
|---------|--------------|
| Method erasure | Type parameters replaced with bounds (or Object) |
| Bridge methods | Generated for polymorphism with covariant returns |
| Cast insertion | Compiler adds casts after generic method calls |
| Varargs | Use `@SafeVarargs` when varargs don't cause heap pollution |
| Overloading | Methods with different generic types may have same erasure |
| Performance | No runtime cost (erasure happens at compile time) |
