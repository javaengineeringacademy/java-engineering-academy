# Nested Classes

## Introduction

Java supports four types of nested classes — inner classes (non-static member classes), static nested classes, local classes, and anonymous classes. While "inner class" and "nested class" are often used interchangeably in casual conversation, they have distinct technical meanings in Java. A nested class is any class declared within another class, while an inner class specifically refers to a non-static nested class that holds an implicit reference to its enclosing instance. Understanding all four nested class types is essential for writing idiomatic Java code, implementing design patterns like Builder and Iterator, and avoiding common pitfalls such as memory leaks and unnecessary coupling. Each type has different scoping rules, access capabilities, and use cases.

## Why This Concept Exists

### The Problem

In complex software systems, helper classes, data structures, and implementation details often need to be logically grouped with their parent class. However, creating separate top-level files for every helper class leads to namespace pollution and makes it harder to understand the relationships between classes. Additionally, some helper classes need access to private members of their parent class.

### The Solution

Nested classes allow you to declare classes inside other classes, keeping related code together. The four types provide different levels of coupling and access, from tightly coupled inner classes (with outer references) to completely independent static nested classes.

### Real-World Analogy

Think of a company hierarchy. A department (outer class) contains teams (inner classes). Some teams work exclusively within the department (non-static inner classes — they need department resources). Some teams are self-contained but still organized under the department (static nested classes — they have their own resources). Some teams are formed temporarily for specific projects (local classes). And some individuals are hired for one-off tasks (anonymous classes).

## Internal Working

### The Four Types at a Glance

| Type | Static? | Outer Reference | Scope | Typical Use |
|------|---------|-----------------|-------|-------------|
| Inner class (member) | No | Yes (implicit) | Class-level | Tightly coupled helpers |
| Static nested class | Yes | No | Class-level | Independent helpers |
| Local class | No | Yes (if in instance context) | Method-level | Method-specific implementations |
| Anonymous class | No | Yes (if in instance context) | Expression-level | One-off implementations |

### Compilation Output

For each nested class, the compiler generates a separate `.class` file named `OuterClass$NestedClass.class`. Anonymous classes get numeric suffixes: `OuterClass$1.class`, `OuterClass$2.class`, etc.

```
```
MyClass.class
MyClass$InnerClass.class
MyClass$StaticNested.class
MyClass$1LocalClass.class  (if multiple local classes exist)
MyClass$1.class            (first anonymous class)
MyClass$2.class            (second anonymous class)
```

### Access to Outer Members

Inner classes and local classes can access both static and instance members of the outer class. Static nested classes can only access static members of the outer class. All types can access public members. Private member access is facilitated through synthetic accessor methods generated by the compiler.

## Syntax

```java
class Outer {
    // Static nested class
    static class StaticNested {
        // Can access only static members of Outer
    }

    // Inner class (non-static member class)
    class Inner {
        // Can access all members of Outer (including private)
    }

    void method() {
        // Local class — visible only within this method
        class LocalClass {
            // Can access final/effectively final local variables
            // Can access outer instance members if called from instance context
        }

        // Anonymous class — creates an instance without a named class
        Runnable r = new Runnable() {
            @Override
            public void run() {
                // Implementation here
            }
        };
    }
}
```

## Easy Examples

### Example 1: All Four Nested Class Types

**Problem Statement**: Demonstrate the declaration and usage of all four nested class types in a single outer class.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

class Company {
    private String companyName = "TechCorp";

    static class Department {
        private String name;

        Department(String name) {
            this.name = name;
        }

        void display() {
            // Cannot access companyName here (static context)
            System.out.println("Department: " + name);
        }
    }

    class Employee {
        private String name;

        Employee(String name) {
            this.name = name;
        }

        void display() {
            // Can access companyName (has outer reference)
            System.out.println(name + " works at " + companyName);
        }
    }

    void createProjectTeam() {
        class ProjectMember {
            private String role;

            ProjectMember(String role) {
                this.role = role;
            }

            void display() {
                // Can access companyName and method local variables
                System.out.println(role + " at " + companyName);
            }
        }

        ProjectMember lead = new ProjectMember("Project Lead");
        lead.display();
    }
}

public class NestedTypesDemo {
    public static void main(String[] args) {
        // Static nested class
        Company.Department dept = new Company.Department("Engineering");
        dept.display();

        // Inner class
        Company company = new Company();
        Company.Employee emp = company.new Employee("Alice");
        emp.display();

        // Local class (created inside method)
        company.createProjectTeam();

        // Anonymous class
        Runnable task = new Runnable() {
            @Override
            public void run() {
                System.out.println("Anonymous class task running");
            }
        };
        task.run();
    }
}
```

**Expected Output**:
```
Department: Engineering
Alice works at TechCorp
Project Lead at TechCorp
Anonymous class task running
```

**Best Practices**:
- Use static nested classes when you don't need access to outer instance members
- Use inner classes for helpers that are logically part of the outer class
- Prefer local classes or anonymous classes for method-scoped implementations

### Example 2: Local Class for Custom Comparator

**Problem Statement**: Use a local class inside a method to create a custom `Comparator` for sorting.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

import java.util.Arrays;
import java.util.Comparator;
import java.util.List;

class StudentSorter {
    static void sortByLastName(List<String> students) {
        class LastNameComparator implements Comparator<String> {
            @Override
            public int compare(String s1, String s2) {
                String last1 = s1.substring(s1.lastIndexOf(' ') + 1);
                String last2 = s2.substring(s2.lastIndexOf(' ') + 1);
                return last1.compareTo(last2);
            }
        }

        students.sort(new LastNameComparator());
    }

    public static void main(String[] args) {
        List<String> students = Arrays.asList(
                "Alice Johnson", "Bob Smith", "Charlie Brown", "Diana Prince"
        );

        System.out.println("Before: " + students);
        sortByLastName(students);
        System.out.println("After:  " + students);
    }
}
```

**Expected Output**:
```
Before: [Alice Johnson, Bob Smith, Charlie Brown, Diana Prince]
After:  [Charlie Brown, Alice Johnson, Diana Prince, Bob Smith]
```

**Best Practices**:
- Use local classes when the implementation is only needed within a single method
- Local classes can access final or effectively final local variables
- Consider lambda expressions as a more concise alternative for single-method interfaces

### Example 3: Static Nested Class for Builder Pattern

**Problem Statement**: Implement a `NetworkConfig` class with a static nested `Builder` class.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

class NetworkConfig {
    private final String host;
    private final int port;
    private final boolean useSsl;
    private final int timeoutMs;

    private NetworkConfig(Builder builder) {
        this.host = builder.host;
        this.port = builder.port;
        this.useSsl = builder.useSsl;
        this.timeoutMs = builder.timeoutMs;
    }

    static class Builder {
        private String host = "localhost";
        private int port = 8080;
        private boolean useSsl = false;
        private int timeoutMs = 30000;

        Builder host(String host) { this.host = host; return this; }
        Builder port(int port) { this.port = port; return this; }
        Builder useSsl(boolean useSsl) { this.useSsl = useSsl; return this; }
        Builder timeoutMs(int timeoutMs) { this.timeoutMs = timeoutMs; return this; }

        NetworkConfig build() {
            if (host == null || host.isEmpty()) throw new IllegalArgumentException("Host required");
            if (port <= 0 || port > 65535) throw new IllegalArgumentException("Invalid port");
            return new NetworkConfig(this);
        }
    }

    @Override
    public String toString() {
        return String.format("NetworkConfig{host='%s', port=%d, ssl=%b, timeout=%dms}",
                host, port, useSsl, timeoutMs);
    }

    public static void main(String[] args) {
        NetworkConfig config = new NetworkConfig.Builder()
                .host("api.example.com")
                .port(443)
                .useSsl(true)
                .timeoutMs(5000)
                .build();

        System.out.println(config);
    }
}
```

**Expected Output**:
```
NetworkConfig{host='api.example.com', port=443, ssl=true, timeout=5000ms}
```

**Best Practices**:
- Use static nested classes for Builders — they don't need the outer instance
- Make the outer class constructor private to force use of the Builder
- Validate in the Builder's `build()` method, not in the constructor

## Medium Examples

### Example 1: Map.Entry — JDK's Use of Static Nested Classes

**Problem Statement**: Demonstrate how `Map.Entry` works as a static nested interface and how to use it effectively.

**Implementation**:

```java
package academy.javaengineering.oop.nestedclasses;

import java.util.HashMap;
import java.util.Map;

class InventorySystem {
    private Map<String, Integer> stock = new HashMap<>();

    void addItem(String item, int quantity) {
        stock.put(item, quantity);
    }

    void printInventory() {
        for (Map.Entry<String, Integer> entry : stock.entrySet()) {
            System.out.printf("  %-20s : %d units%n", entry.getKey(), entry.getValue());
        }
    }

    String findLowStockItem() {
        Map.Entry<String, Integer> lowest = null;
        for (Map.Entry<String, Integer> entry : stock.entrySet()) {
            if (lowest == null || entry.getValue() < lowest.getValue()) {
                lowest = entry;
            }
        }
        return lowest != null ? lowest.getKey() : null;
    }

    public static void main(String[] args) {
        InventorySystem inventory = new InventorySystem();
        inventory.addItem("Laptops", 50);
        inventory.addItem("Keyboards", 200);
        inventory.addItem("Mice", 15);
        inventory.addItem("Monitors", 35);

        System.out.println("Inventory:");
        inventory.printInventory();
        System.out.println("Low stock: " + inventory.findLowStockItem());
    }
}
```

**Expected Output**:
```
Inventory:
  Laptops              : 50 units
  Keyboards            : 200 units
  Mice                 : 15 units
  Monitors             : 35 units
Low stock: Mice
```

**Code Walkthrough**: `Map.Entry<K,V>` is a static nested interface within `Map`. It represents a key-value pair. By making it static nested (not inner), `Entry` instances can exist independently of any `Map` instance, which is essential for entries that outlive their parent map.
