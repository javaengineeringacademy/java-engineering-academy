# Content Quality Checklist

Every topic must meet these requirements before being considered complete.

---

## Required Sections

- [ ] Overview section
- [ ] How it works section
- [ ] Why it works this way section
- [ ] Memory implications section
- [ ] Performance characteristics section
- [ ] OpenJDK implementation section (where applicable)
- [ ] Code examples (runnable)
- [ ] Common pitfalls
- [ ] Best practices
- [ ] When to use / when NOT to use
- [ ] Interview questions (minimum 5)
- [ ] References

---

## Content Requirements

- [ ] All code examples compile and run
- [ ] Code examples include expected output
- [ ] Complex concepts include diagrams or visual aids
- [ ] Technical terms are defined on first use
- [ ] No unexplained abbreviations or acronyms
- [ ] External links are verified and working
- [ ] References include official documentation
- [ ] Interview questions include answers

---

## Quality Standards

- [ ] Writing is clear and concise
- [ ] No spelling or grammar errors
- [ ] Consistent formatting throughout
- [ ] Tables are used for comparisons where appropriate
- [ ] Bullet points break up long paragraphs
- [ ] Code blocks use proper syntax highlighting
- [ ] Section headings follow standard hierarchy

---

## Technical Accuracy

- [ ] All Java version references are correct
- [ ] API descriptions match current JDK documentation
- [ ] Performance claims are backed by data or benchmarks
- [ ] Memory behavior is described accurately
- [ ] Thread safety implications are addressed where relevant
- [ ] Edge cases are documented

---

## Completeness

- [ ] Topic covers both beginner and advanced aspects
- [ ] Real-world use cases are included
- [ ] Alternative approaches are mentioned
- [ ] Migration notes provided for deprecated features
- [ ] Testing examples are included where applicable
- [ ] Error handling patterns are demonstrated

---

## Checklist Usage

1. Complete all sections of the topic using the template
2. Work through this checklist item by item
3. Mark each item as complete with [x]
4. Address any failed items before publishing
5. Request peer review after all items are checked
